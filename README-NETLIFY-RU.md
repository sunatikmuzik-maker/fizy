# FIZY Journal · by fizy — для Netlify

Это новая сборка специально для Netlify: Netlify Functions + Netlify Blobs.
Отдельные VPS, Docker, SQLite и Supabase не требуются. Прежний архив с SQLite
для этой схемы не подходит. Интерфейс, диаграмма, цитаты и локальный ИИ сохранены.

## Как опубликовать
1. Распакуйте архив. Создайте репозиторий GitHub и загрузите СОДЕРЖИМОЕ папки
   FIZY-Netlify: package.json, netlify.toml, public, server, netlify, shared.mjs,
   check-build.mjs, tests. Не загружайте только папку public.
2. В Netlify выберите Add new project → Import an existing project → GitHub.
   Выберите репозиторий. Если проект уже есть, подключите репозиторий к нему
   через настройки сборки/Continuous deployment.
3. Настройки: Base directory — пусто, Build command — npm run build,
   Publish directory — public, Functions — netlify/functions.
   Эти настройки уже есть в netlify.toml. Netlify установит npm-зависимости.
4. После первого deploy скопируйте основной HTTPS-адрес проекта:
   например https://имя-проекта.netlify.app.
5. Project configuration → Environment variables → Add variable:
   PUBLIC_URL = ваш основной HTTPS-адрес, без пути.
   Область действия должна включать Functions (или All scopes).
   Пример приведён только как образец, не используйте чужой адрес.
6. Запустите повторный production deploy. Откройте основной адрес сайта.
7. Зарегистрируйте тестовый аккаунт, сохраните код восстановления, добавьте две
   сделки с USD-результатом. Выйдите и войдите снова: записи должны сохраниться.
   Проверьте второй аккаунт: он должен начинать с пустого журнала.

ВАЖНО: простое перетаскивание public/ в Netlify Drop публикует только интерфейс
и НЕ собирает серверные функции. Используйте сборку из GitHub.
Репозиторий должен содержать netlify.toml в корне выбранной Base directory.
Не выставляйте корень проекта как Publish directory: публикуется только public.
Никакие пароли Netlify, PAT или ключи Blobs не нужно вставлять в браузерный код.
Netlify автоматически предоставляет функции доступ к хранилищу своего проекта.
Сборка не опубликована автоматически: доступа к вашему аккаунту Netlify у меня нет.

## Почему аккаунты сохраняются
Используется site-wide store Netlify Blobs: fizy-journal-v1.
Новый production deploy того же проекта не сбрасывает этот store.
При создании другого проекта Netlify или смене FIZY_STORE_NAME данные не переносятся.
Каждая запись содержит один аккаунт, его журнал и до 10 активных сессий.
Чтения strong consistency, записи условные по ETag. Гонки регистрации и сохранений
не должны молча перезаписывать чужую/более свежую версию.
PUBLIC_URL ограничивает API основным доменом: Deploy Preview и branch-домены
не получают доступ к API этой сборки. Для отдельного staging-проекта используйте
отдельный Netlify project. Не выдавайте недоверенным людям права на код/деплои:
администраторы Netlify технически имеют доступ к Blobs и пользовательским данным.

## Безопасность и ограничения
Пароли — scrypt + соль. Код восстановления показывается один раз, сервер хранит
его хеш. Восстановление сбрасывает все активные сессии. Cookie — Secure,
HttpOnly, SameSite=Strict, срок 7 дней. Есть Origin/CSRF и распределённый счётчик
попыток входа в отдельном store fizy-journal-v1-rate. При превышении ждите 10 минут.
Сессии после 7 дней отбрасываются при проверке/новом входе.
При удалении аккаунта пароль, журнал и сессии стираются из рабочей записи;
остаётся технический маркер удаления по хешу логина для защиты от гонок.
Счётчики ограничений используют хеши и не содержат паролей/сделок. Их очистка
владельцем, политика резервного хранения и внешние бэкапы отдельно настраиваются.
Регистрацию можно закрыть переменной ALLOW_SIGNUP=0 + новый deploy.

Рекомендуется для небольшого начального проекта: записи Blobs включают целый
журнал, максимум 2000 сделок и около 2 МБ на запрос. Перед массовым запуском
нужны нагрузочные испытания, антибот-защита, мониторинг, резервные копии,
проверка безопасности и юридическая политика с контактами владельца.
Данные не зашифрованы сквозным шифрованием. Никогда не храните ключи бирж в заметках.
Сайт-wide хранилище — не автоматический резервный архив. Экспортируйте данные
и настройте защищённые копии; удаление проекта/Blobs может уничтожить аккаунты.
У Netlify есть квоты и правила оплаты: проверьте свой тариф. Бесплатный локальный
ИИ не означает неограниченный бесплатный хостинг или бесплатные операции Blobs.

## Перенос старых сделок
В прежнем приложении экспортируйте JSON. На новом сайте создайте аккаунт,
откройте Сделки → Импорт JSON. Импорт заменяет журнал после подтверждения.
Старые пароли/аккаунты SQLite автоматически не переносятся.
Результаты R не превращаются в USD: заполните денежные результаты отдельно.

## ИИ
Остаётся бесплатная локальная модель Qwen2.5 0.5B через Transformers.js 3.7.2.
Нажмите загрузку и подтвердите несколько сотен МБ трафика. Нет API-ключей
и платы за генерацию, но устройство тратит память/процессор. Текст вопросов
не отправляется облачной модели. Модель может ошибаться; котировок в реальном
времени нет. CDN и Hugging Face должны быть доступны. Фактическая генерация
в среде сборки не проверялась, как и финальный deploy в вашем Netlify.

## Если не работает
- PUBLIC_URL missing / неверный адрес: укажите точный production URL в Functions
  environment, выполните новый deploy и откройте основной адрес, не preview.
- Ошибка 404 на /api/me: не развернулась функция api; проверьте Functions и deploy log.
- Ошибка 500 при сохранении: откройте function logs, проверьте Blobs и квоты проекта.
- Build failed: пришлите текст ошибки сборки без ключей и секретов.
- Старые данные после смены устройства: войдите в тот же аккаунт на том же сайте,
  обновите страницу или нажмите Аккаунт → Обновить журнал.

## Проверки
npm test запускает тесты серверной логики с тестовым хранилищем, поддерживающим
сильное чтение и условные записи. Это НЕ проверка облачной службы Netlify.
Не тестировались в этой среде: установка npm по сети, настоящая сборка Netlify,
облачное хранение, биллинг и генерация ИИ. Обязательна проверка после публикации.
